## Variant: Split Workbench

### Design stance

Keep Projects visible while Christian moves between the selected Project, Global Experiments, records, and decisions.

### Key choices

- Layout: persistent Project rail plus a wide Project workspace.
- Density: medium-high, with the Project hierarchy visible in one screen.
- Primary interaction: Project selection and horizontal Project tabs.
- Universal action: `Add existing` opens the same typed attachment form used elsewhere in BMS.
- Result behavior: records reopen their canonical specialized viewer.

### Trade-offs

- Strong at: daily work across several active Projects and experiments.
- Weak at: small mobile screens, where the Project rail becomes a horizontal selector.

### Best for

- The normal Project Manager implementation.
- Operators who keep several related simulations and molecular records open across a research program.
