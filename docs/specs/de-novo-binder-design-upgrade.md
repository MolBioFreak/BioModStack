## 1. Product and authoring

The experience is one coherent product: choose format/objective and compatible generator; acquire and inspect target/template/seed; configure the native request; choose the existing placement; run; inspect model-native results; stop or select a compatible subset for optional operations; inspect/compare descendants and repeat. Use the delivered BC2 workspace as the interaction reference, not a universal scientific schema.

The binder starting-generator lineup is RFantibody, BoltzGen, PPIFlow and BC2. Existing BMS RFD3 generation is unconditional monomer design in the separate De Novo Design product, not a fifth target-conditioned binder generator. Preserve its separate generation/local-redesign routes without adding them to binder-generation acceptance or relabeling their output as a binder. Compatible imported structures may still use model-appropriate selected operations, without implying target binding. Preserve generator-only exit, supported pause/review, independent selected operations, historical request interpretation, saved configurations, retries and native results. Do not enable the disabled historical `binder_design.yaml` pipeline as a shortcut. PPIFlow has two distinct product roles: independent initial candidate generation alongside BoltzGen/BC2, and separately selected, narrower operations within refinement. Do not define the first role by the current seeded partial-flow wrapper. Native input/checkpoint limits must be verified for the generation path itself; a target/template requirement is not the same thing as requiring a previous generated candidate.

### Source and template minimum

Every generator workspace must expose all applicable existing acquisition mechanisms: local upload, PDB ID, RCSB search, saved run/Design, configured structure/preset library and Project resources. Reuse current services; connect any missing adapter instead of creating a second catalogue. Engine-native sequence inputs remain available where supported.

The source area includes full Mol* structure inspection and synchronized sequence/chain/residue selection; target and template/seed can each be inspected without changing their roles. Show source identity, exact document/model/state, role and native versus converted format. Distinguish structural framework/scaffold/template, seed complex, sequence template and saved workflow configuration. This requirement applies to the four binder starting generators; it does not expand the separate RFD3 product into target-conditioned binder design.

Support multiple targets/states and negative/detarget inputs where the model natively does. Do not collapse them to one global target. A required seed complex cannot be manufactured by automatically merging independent target/framework uploads. A sequence-only input does not gain fabricated coordinates or structure-numbered hotspots. A mode that does not use a scaffold does not gain a mandatory template.

Keep coordinate masks bound to their actual source. Preserve author/label chain and residue identities, insertions and assembly/model distinctions where represented. Perform format conversion only at a real native consumer boundary, with preserved native bytes and mapping; accepting a file in the picker does not prove every engine consumes it.

### Settings, drafts and project context

Each model retains one relevant scientific schema, typed browser/API controls, native compiler, requested/effective settings and result authority. Use task-focused sections, selectors, switches, precise numbers and typed identity/list/map controls. Advanced settings remain accessible; raw JSON is supplementary. Do not invent slider limits, scientific defaults or fallback methods.

Engine/mode/section switching, late defaults, save/reopen/clone/retry and Project workflow-setup editing preserve explicit false/zero/null/empty values and populated sources. Restore an existing destination draft first; adopt only compatible shared inputs into untouched fields. Placement does not change scientific settings. BC2 retains its existing preview/digest semantics; other engines do not acquire them merely for visual consistency.

Use the existing project manager, setup persistence, launch context and resource links. Both standalone and Project-originated authoring use the same model-owned controls. Project membership and workflow-step relationships are separate from scientific ancestry and the project containing an imported source. Preserve the caller's explicit destination; never infer a destination from a template's provenance. Complete missing generator/selected-action adapters and reopening, without a second project or workflow engine.

## 3. Native results and repeated selection

Reuse Job/Design, JobArtifact/scientific datasets, the global workbench and model-native readers. No universal binder score, parallel candidate database or workflow-local numerical store.

BC2 retains distinct campaign/arm, attempt/claim, scored draw, passing draw, retained sequence and structure document/state records. Native rank is metadata, not identity. Preserve explicit scored-to-retained producer joins, multichain sequences, target ordering/weights, per-attempt settings and intentionally absent outputs. Structureless observations remain native records, never placeholder PDBs. Multiple state structures do not inflate accepted-sequence counts.

The publisher consumes the declared native campaign root beneath the owned Job output, not a guessed directory. Preserve historical publication inventories, nested artifacts and ancillary/resume state. Local output and returned remote output use the same reader. Native metrics/ranks, tables, pagination, structure/sequence selection, comparison, export, saved views/capture/annotations where applicable and Job settings reopen through existing owners.

Every selected operation resolves persisted source/root ownership and exact Design/document/state. Keep original CIF/mmCIF authoritative and checked derivatives for PDB-only consumers. Do not infer scientific identity from filename, stem, ordinal, sequence equality or global-ID existence. Same-root siblings retain per-item parents; unrelated selections keep existing ownership behavior. Source selection, display focus and project membership are separate.

Preserve immutable selected bytes locally and remotely. Reuse prepared remote snapshots after review; do not call selection/materialization again. Native row links must land on the exact candidate/document rather than only a generic Job page. Selected identities survive pagination and reopen through existing persistence owners.

Changed sequences or coordinates are descendants with fresh validation state. Parent evidence stays attached to the parent. A read-only assessment cannot silently modify the candidate, native rank or acceptance. Optional-stage failure preserves valid primary/earlier results through production finalization, manual return, retry and re-ingestion.

## 4. Optional operations

Deliver independently selectable repack, anchor analysis, supported partial flow, sequence redesign, prediction/validation and analyses. Off means no execution, coordinate mutation, dependency acquisition or hidden downstream operation; collapsing settings does not toggle execution. Retain supported legacy branches without introducing them as generic defaults or substituting a different scientific method.

- Generic sequence redesign uses existing FA-MPNN/ProteinMPNN contracts and explicit source-bound designed/fixed regions. Antibody CDR conveniences apply only to appropriate modes.
- Repack and anchor analysis remain separate. Repack-off preserves input coordinates; anchor-only is read-only. Report actual changed coordinates rather than shell membership.
- PPIFlow initial generation is a first-class alternative to BoltzGen/BC2, independent of a prior generator or refinement round. Its generation-native request, input preparation, controls and output contract must be established separately; the current `generator_backbone_refine` wrapper is not proof that this intended role is finished. Within the optional loop, preserve the distinct partial-flow/refinement/maturation uses and their actual supported formats/checkpoints and role restrictions. Do not copy those narrower restrictions onto generation without native evidence. Keep sample identity and truthful zero-yield accounting for each role.
- Prediction uses the selected model's real request and native outputs. Preserve every sample/metric pair, target state and missingness. Repair saved ESMFold2 hydration without substituting another predictor. Changed descendants do not inherit previous confidence.
- Caliby uses its existing selected runner and native controls/masks, not a simplified new method. Qualify selected input/context/checkpoint and full output identity separately from source implementation.
- Full global FrustraMPNN retains its settings, native landscape, scheduler fan-out, structure/sequence-linked workbench, statistics, exports, captures and exact parent/document identity. Label it binder-local exploratory evidence, not direct target-conditioned or cross-chain energetics. Do not concatenate binder and target to manufacture a native context.
- Physics uses the existing typed GROMACS/MD starting-structure handoff, settings and results. Do not translate OpenMM settings into an assumed equivalent protocol, choose force field/solvent/restraints implicitly or strip BC2's separate native optional relaxation.

LigandMPNN interface-context and blind-pose actions stay independently selectable on exact candidate/state subsets. Reuse their distinct existing APIs, wrappers and raw result readers. Ordinary LigandMPNN chemistry-context redesign remains a different contract. Record actual input conditioning and native evidence honestly: supplied geometry is not independent pose recovery, sequence-only cofolding alone does not demonstrate pose recovery, and neither is measured binding/affinity. Qualification of the protein-interface interpretation remains an evidence task under separately approved scientific methods and benign inputs, not invented thresholds or a new generic validation engine.

Do not implement cutoff-policy CRUD, saved classification/reclassification, automatic dual-pass/fail, automatic candidate rejection or diagnostic prerequisites. Preserve raw independent results, mixed evidence, errors, skips and uncertainty without turning any of them into a launch/continuation refusal. Pairwise Frustratometer is outside this iteration.

## 7. Acceptance identifiers

These identifiers retain the original scope, with superseded diagnostic policy removed and source/project coverage clarified. See the controlling spec for current evidence, residual work and owner. Source/test presence, UI renders, an installed image and a fixture run are not native acceptance.

- **A01 — Product structure:** every retained generator and applicable format has model-correct authoring, full target/template/seed viewing and acquisition, and coherent standalone/Project entry and return. No cosmetic generic label over a VHH request.
- **A02 — Full native BC2:** complete relevant field/action/modality/objective/input/output/lifecycle coverage through UI/API/compiler/persistence; no unexplained omissions or raw-JSON-only path.
- **A03 — Request fidelity:** populated sources, explicit values, native settings and destination project/setup survive browser/agent, save/load/clone/retry, section/engine switches and emitted native requests. Respect each existing preview contract.
- **A04 — BC2 accounting:** claimed/emitted/scored/passing/retained counts, explicit producer joins, states, adaptive settings, suppressed artifacts, sweeps, trajectory-only and zero yield remain truthful; native continuation is not a fresh run.
- **A05 — Per-model results:** model-native tables/metrics/ranks, applicable views/comparison/export and requested/effective settings reopen from Job, Results and Project after restart/worker loss, without competing numerical authority.
- **A06 — Selection and lineage:** exact source/root/Design/document/state/format/roles and immutable inputs survive rounds and branches; no foreign-ID acceptance or basename collapse. Destination project is preserved separately from source provenance.
- **A07 — Optional loop:** all retained generators have compatible selected continuation; real BC2-produced candidate handoff and another selected descendant round are demonstrated. Generator-only exit and unrequested operations remain inert.
- **A08 — Refinement semantics:** independent operations, masks/roles/checkpoints, native sample cardinality and exact predictor pairing; coordinate/sequence changes create fresh descendant evidence.
- **A09 — Analyses and diagnostics:** full FrustraMPNN, Caliby and separate raw LigandMPNN-context/blind-pose operations execute and reopen with honest applicability/conditioning. Qualification is reported separately; no classifier or cutoff machinery is required.
- **A10 — Failure isolation:** optional failure preserves primary/earlier candidates; zero yield, failure, missing and not-requested stay distinct; retry/replay does not duplicate identities or erase parents.
- **A11 — Corrections:** C01–C14 and W01–W08 retain substantive review, necessary fixes, focused regressions and integrated evidence; concrete source/project/handoff and code/processing defects join the same owner-level work rather than another audit programme.
- **A12 — Local/remote parity:** authorized actual generation, selected operations, return and reopen use the existing bridge and model-native contracts, including Project-originated requests. Explicitly account for each operation's placement owner.
- **A13 — Efficiency/lifecycle:** measured source/UI, Python/data-processing and orchestration performance as well as cold/warm behavior and asset/cache reuse; truthful resume/review continuation; approved stop/interruption/return/re-ingestion recovery and worker-offline reopen. No speed claim from changed scientific work.
- **A14 — Integrated delivery:** combined-tree focused tests, authorized representative native runs, separately verified deployed API/frontend/worker identities when deployment is authorized, clean source and removal of superseded active code.
