# AtomWorks Studio editor package preparation (S02 partial)

`sh scripts/prepare_atomworks_studio.sh NEW_VENV atomworks_studio-0.0.5-py3-none-any.whl` prepares an isolated Python 3.12 editor environment using `uv`; it does not start a service. Obtain the wheel from PyPI; the preparer verifies SHA-256 `da60857d956a65d1b4dfe439326303b0a0c97b6fa520cece96fa02d041d0524d` and all wheel RECORD entries before installation. Published v0.0.5 corresponds to Studio commit `04fe5fbd03fea8b7d49a767156d7d33bd10e5d13`. CPU Torch 2.7.1 is installed first; no Gradio extra, weights or model runner. The constraints record the Linux x86-64 Python 3.12 versions exercised locally, but do not hash-lock transitive distributions or constitute a final release SBOM. Build tooling, Python and OS packages are also not digest-pinned.

The installed index is modified to add upstream's `atomworks-studio-service-worker=off` meta tag. This deliberately changes an installed wheel member after RECORD verification; future artifact receipts must record that modification. The preparer copies the Patinae BSD notice omitted from the published wheel to `share/atomworks-studio/notices/`. The complete transitive notice set and final distributable remain unreviewed. This opt-out prevents new registrations; it does not remove or neutralize a previously registered same-origin worker. Do not serve the editor at an origin with an existing Studio worker until cache/worker migration is designed and tested.

**Not a private host yet.** The checked-in BMS ingress does not supply distinct authenticated user principals: `docker/web/nginx.conf` clears `Tailscale-User-Login` and sends the same server-owned `X-BMS-CM-Proxy-Secret` for all `/api/` requests; `routers/experiment_workspaces.py::_authenticated_principal` maps that secret to `local-application-operator`. The production Tailnet proxy also clears the login. Repository assignments of `request.state.authenticated_principal` found for this boundary are test fixtures, not a production middleware. Consequently this proxy secret cannot establish cross-user ownership, and passing it through as a Studio owner would merge users. A real per-user authentication authority and its trusted ingress path must be selected before private hosting can safely be wired; no such endpoint or iframe contract is provided by this package.

Upstream defaults to a shared `local` document owner and has absolute-root API/static paths. Never expose it directly. BMS integration must route all editor assets and both API route forms through an authenticated, CSRF-protected private boundary, map the trusted BMS principal to Studio's owner context, and bind iframe origin, actual `contentWindow` and current owned `session_id` independently. A frame-ancestors CSP is not API authentication. The parent owns the shared ingress/frontend integration. Isolate the editor origin or provide a safe same-origin path strategy, ensuring Studio cannot control BMS caches; validate direct access, spoofing and cross-user session isolation with the real ingress. Existing identity and CSRF patterns need explicit integration, not trust in client-supplied identity headers.
