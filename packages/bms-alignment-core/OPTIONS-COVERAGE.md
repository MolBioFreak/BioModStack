# Family MSA settings coverage (incremental)

## MAFFT 7.525 source/manual increment

Source: the installed `/opt/msa/bin/mafft` shell wrapper in the pinned SIF; its build script pins [7.525 source](https://mafft.cbrc.jp/alignment/software/mafft-7.525-without-extensions-src.tgz) SHA256 `edb34ae9b26d6b55328c18fa060ed741bca8cd599c2f4f8fad0e0871c8082265`. Semantics and applicability were cross-checked against the [upstream manual](https://mafft.cbrc.jp/alignment/software/manual/manual.html), which is not itself version-pinned. The installed wrapper recognizes substantially more options than `--help`; its textual mentions also include internal, unavailable-extension and commented options, so mentions are not a verified supported-option inventory.

The SIF native tests run E-INS-i with local/skip penalties, consistency weight, BLOSUM, no-FFT and seed; L-INS-i DNA with Kimura; and separate JTT and TM protein calls. Receipts persist requested values and argv, not verified native-effective algorithm settings; a zero exit and nonempty output do not establish the effect of every flag or scientific accuracy. Auto/strategy interactions, model conflicts, all molecule combinations and browser save/retry parity remain unqualified.

The request owner's `AlignmentRequest.model_json_schema()` is served at `/api/family-msa/settings-schema`; the editor derives fields and defaults from a bundled copy generated from that same model. `test_bundled_editor_schema_matches_request_owner` checks the copy against the owner; regenerate it whenever the model changes. Independently deployed frontend and API versions can still diverge; the editor reports a schema mismatch or an unavailable comparison without blocking execution. The schema inventories accepted BMS settings, not every upstream option or a proof of native behavior.

Inspected against the scratch CPU SIF: MAFFT 7.525 `--help`, FAMSA 2.5.2 `-help`, MUSCLE 5.3 `-h`, TWILIGHT 0.3.0 `-h`. For the existing full-family alignment modes, this increment adds MAFFT E-INS-i, `--op` and `--ep`; FAMSA `-r`, `-sm`, `-go`, `-ge`, `-tgo`, `-tge`, `-dist`, `-gsd`, `-gsl`, `-dgr`, `-dgo`, `-dsp`; TWILIGHT `--length-deviation`, `--max-ambig`, `--max-len`, `--min-len`, `--write-filtered`, `--write-prune`, `--check`. Existing MUSCLE align/Super5, permutation, perturbation and ensemble controls were retained.

Additional controls: MAFFT `--retree`, `--maxiterate`, `--reorder`, `--quiet`; FAMSA and TWILIGHT verbosity. Explicit MAFFT iteration values replace strategy defaults in the compiled command. MAFFT `--auto` interactions with explicit overrides have not been established; the requested arguments are passed through, not silently discarded.

Known unsupported items from those help surfaces: MAFFT `--clustalout`, `--dash` and additional CLI options beyond its brief help; FAMSA imported guide tree, profile-profile input, `-gt_export`, `-dist_export`, `-square_matrix`, `-pid`, `-gz`, `-gz_lev`; MUSCLE resampling, dispersion, max-CC, EFA conversion/explosion, confidence and related `-maxgapfract`, `-minconf`, `-html`, `-jalview`; TWILIGHT merge/add inputs, `--temp-dir`, `--keep-temp`, `--compress`, `--overwrite`, custom `--matrix`, `--blosum`, non-accurate mode. Help/version flags are not request settings. Some are distinct workflows or output formats rather than missing controls for approved full-family modes. This list is not an exhaustive audit of MAFFT's complete upstream CLI or hidden/native source options; full source-grounded inventory remains open.

The optional native probe exercises one nondefault combination per engine and checks exact settings in persisted native receipts; it does not qualify every option, all supported molecule types, every combination, actual output semantics of auxiliary TWILIGHT files, or scientific accuracy. No observations were turned into execution or success gates. Typed browser transport and real HTTP persistence must be assessed separately.

The pinned 0.3.0 help spells the auxiliary flags `--write-filtered` and `--write-prune`: the compiler now translates both underscores correctly. The native nondefault test invokes both, but does not assert auxiliary output contents. Compiler/JSON round-trip tests cover zero-valued numeric controls, both boolean states and representative null omission; a zero accepted by the BMS schema is not thereby established as native-supported. The schema-driven UI preserves numeric enum types rather than key-specific coercion. These tests do not establish exhaustive browser save/retry or end-to-end API parity.

Project switching now initializes each engine from its own defaults plus the newly opened draft rather than retaining unspecified settings from the previous Project. The TWILIGHT leaf-mapping text also refreshes when a different draft is hydrated. These repairs have mounted frontend regression tests with mocked Project services; they do not establish a real browser-to-API save/reopen or retry/resubmit journey. The available scratch harness was based on an older commit and schema, so a browser session against it cannot qualify this revision. A current-version isolated browser/API/compiler journey, including false/zero/null and captured nondefault argv on retry/resubmit, remains unverified.
