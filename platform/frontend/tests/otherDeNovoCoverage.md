## Required capabilities still open / owner handshake

- **RFD3 symmetry:** current endpoint publishes `type: symmetry` without the installed SymmetryConfig fields. Complete typed authoring needs that owner inventory; no guessed schema or upgrade was introduced. Exact source-conditioned MODEL/insertion-code/unindexed-map and historical dispatch acceptance still needs the broader receiving suite.
- **La native evaluation:** there is no evaluation execution owner in this frontend slice. Implementing one requires the backend/runtime lane; generation is explicitly labelled not evaluation.
- **La atom boundaries:** native atom specs encode residue/atom names, not independent altloc constraints. Existing motif-only materializer still refuses unrepresentable insertion-code/chain-I graphical conversions; manual native sources remain available. No new launch gate. Pinned-native parser differential qualification remains pending.
- **DISCO file import to editable rows:** retained native JSON files still run by their existing managed path. The new explicit row editor does not silently read/copy those files into `pcad_disco_jobs_json`, because relative FILE_ custody is bound by the backend to the original document owner. A checked import/materialization seam is required to make that conversion safely. Integer atom-map execution remains explicitly unqualified.
- **Effective scientific defaults:** settings schemas and seven checkpoint pairs are source-owned; full composed selected-profile numerical values are not available in this endpoint. UI does not invent them or populate sparse overrides merely for display.
- **Lifecycle/results:** actual Template two-save/cold GET, Project Prepare, browser-to-real-API persistence, full per-field edited normalizer matrix, native runtime outputs, Results and GPU/remote acceptance remain integrator/native-owner work. This lane makes no claim of full UI completion.
