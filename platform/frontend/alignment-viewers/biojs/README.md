# Experimental BioJS MSAViewer adapter

AlignmentPage registers the real BioJS viewer. `pnpm dev` and `pnpm build` use pnpm workspace-locked dependencies and generate the locally embedded vendor JS/CSS; generated `dist/` is not committed. Direct Vite or tests require `pnpm --filter @bms/biojs-viewer build` first. Build copies the published `msa@1.0.3` prebuilt bundle and applies a checked compatibility patch for Array.prototype.at; it does not rebuild upstream source. Two consecutive builds produced identical vendor JS and CSS SHA-256 values `2c5c8f25fc4d36928c374c7467279845a43dc2a7ba00250d9d954cd4b4c34aa6` and `cdc242e7275b5934ef03d038a7083f08b645e7255e0f9e632f5a283ce176b13b` locally. This is not proof of source-to-bundle equivalence or reproducibility across environments. The upstream BSL-1.0 license is copied; full bundled dependency/license closure is not established.

Rows and labels are included once in a sandboxed opaque srcdoc; no alignment or selection is sent to the frame after load. Selection messages require the frame window, channel and per-frame random token, then map row index and zero-based column via anchorAt. Upstream handles residue selection on double-click; the adapter translates a canvas click into that event. External selections, shared marks and saved views are not rendered. Changing rows or identities recreates the frame. Labels pass through legacy renderer templates; untrusted-label HTML injection has not been fully audited. Browser synthetic tests cover two residue coordinates and a gap, not scroll, zoom, large inputs, all symbols, malicious labels or all browsers.

The frame disables menus, drop import, forms, workers, external images and connections; legacy templates require unsafe-eval inside the frame. These measures are not a confidentiality boundary against a malicious bundle: executing code can navigate its own frame with data in the URL. Source/window/token checks do not authenticate code already inside the frame, and parent XSS, extensions, CSP inheritance, alternate channels and production deployment remain unqualified. Trust/review the pinned bundle; do not claim arbitrary malicious code is confined or use private data on the strength of this experiment. Synthetic tests do not establish zero network requests in every browser.

The earlier isolated npm audit reported 7 packages: 5 moderate, 2 critical (request and form-data). They are not two critical root advisories: request inherits the critical severity of form-data. `msa -> bio.io -> request -> form-data` resolves the vulnerable version. GHSA-fjxv-7rqg-78g4 affects multipart boundary predictability below 2.5.4; GHSA-hmw2-7cc7-3qxx concerns CRLF injection below 2.5.6. Exploitation depends on relevant multipart use and attacker-controlled inputs; neither exploitability nor absence of affected code in the prebuilt bundle is established. Import/share UI is not instantiated, but that does not prove unreachable code. Overriding npm dependencies would not repair the separately prebuilt browser bundle. Other request-related moderate advisories remain; request is deprecated. The old Vite high advisory is removed from this isolated package by removing Vite. No claim is made about the main frontend dependency tree. Full dependency source, transitive licensing and security review remain open.
